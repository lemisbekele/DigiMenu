Design language · draft 1 for approval

One calm workspace for the whole café

Every DigiMenu screen, from the customer's phone to the kitchen wall, is built from the same few parts on the same light ground. Only the colours come from the old design. Everything on this page is drawn with the tokens it describes, so what you see is what the app would use.

Where it comes from

The language is built from your two references and three more in the same family. This is what each one contributed.

Tave coffee shop POS

The three-part workspace: grouped navigation on the left, a grid of photo cards in the middle, the order being built on the right. Lots of white, thin lines, small quiet labels, category chips above the grid.

Cafe Burito order management

The records screen: a row of headline numbers with a trend, one toolbar holding the Open/Closed switch, search and the single main action, then a dense table with soft coloured status pills.

Kitchen display references

Light ticket columns where the header band carries the status colour and the timer, so the state reads from across the room. One action at the bottom of every ticket.

QR ordering references and WCAG 2.2

Phone menus lead with photos, keep one Add per item and pin the order bar to the bottom. From the accessibility standard: 4.5:1 text contrast, status never shown by colour alone, 44px touch targets.

Five principles

1. White space does the work

Light ground, white surfaces, hairline borders. No shadows except on things that float above the page.

2. Green means go

Green marks the one main action on a screen and where you are. Nothing decorative is green.

3. Status is a soft pill

A pale tint, a dark word and a dot. The same five states and colours on every screen.

4. Same frame, different content

Navigation, page title, toolbar and content always sit in the same places. A role changes what is listed, never where it is.

5. Food gets the pictures

Photos appear only on things you can eat or drink. Everything else is text and numbers.

Colour

The palette is the existing one, unchanged. What is new is the rule for where each colour may appear. Roughly: nine parts neutral, one part green, and status colours only on status.

The five states

In linePreparingReadyLatePaid

Measured contrast of each word on its tint, light theme: in line 9.1, preparing 6.2, ready 6.8, late 6.7, paid 4.9. All pass the 4.5:1 standard. White on the green button is 5.2.

The same parts, phone size

The item card is the counter's product card turned sideways. Chips, prices and the green button are identical. The order bar is the order panel's last row, pinned to the bottom of the screen.

On phones the staff navigation becomes a tab bar along the bottom with the same links.

How every page is laid out

Left
Navigation, 188px, grouped under small headings. The links depend on your role; the position never changes.
Top
Page title with one line of context under it. The single main action sits at the top right.
Toolbar
Optional. View switch on the left, filters and search on the right.
Content
One of three shapes: a card grid (menu, tables, tickets), a table (orders, cafés, users, logs) or a form (settings).
Right
Optional detail panel, 264px, for the thing being worked on: the open order, a selected café, an item being edited. It replaces most pop-up dialogs.

Rules that keep it uniform

  • Colours, sizes and spacing come only from the tokens. No one-off values in a page.
  • One green button per screen or panel.
  • Status is always a pill with a dot and a word, from the same five states.
  • Numbers are right-aligned in tables and use fixed-width digits.
  • Short labels stay on one line. Long text is cut with an ellipsis; it never breaks a row's height.
  • Every list has a loading, an empty and an error state that says what to do next.
  • Light and dark use the same parts. Only the token values change.
