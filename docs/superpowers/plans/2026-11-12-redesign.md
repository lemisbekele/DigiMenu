# DigiMenu Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the visual layer of every DigiMenu screen on one design language so the whole app looks like one product, keeping only the colour palette and all behaviour.

**Architecture:** Tokens in `src/theme.css`, one shared stylesheet `src/ui/ui.css` (class prefix `ui-`), a handful of thin React components in `src/ui/`, and the existing single page frame `src/pages/RoleLayout.jsx`. Areas migrate one at a time; each area's legacy CSS is deleted when it lands, ending with `src/App.css` removed.

**Tech Stack:** React 19 + Vite, plain CSS (no new dependency), lucide-react icons, Vitest + Testing Library, Google Fonts (Bricolage Grotesque, Figtree, Noto Sans Ethiopic).

**Spec:** `docs/superpowers/specs/2026-11-12-redesign-design.md`. Visual source of truth: `docs/design-language.html` — open it; its `<style>` block holds the exact values for every part named below.

## Global Constraints

- Look only: no change to routes, features, data, permissions or what copy means. Behaviour tests pass unchanged; tests asserting class names may be updated.
- Colour values in `src/theme.css` are not edited, light or dark.
- Green (`--brand`) only on the one main action per screen/panel and on the active navigation link. Status colours only on status.
- Status is always `StatusPill` (dot + word); five tones: `waiting`, `preparing`, `ready`, `late`, `paid`.
- Type sizes only 12, 13, 14, 16, 20, 28. Display font only on page titles, table numbers, headline figures.
- Spacing only 4/8/12/16/24/32. Radius only 8/12/16/full. Controls 36px, 44px on touch.
- No hex colours outside `src/theme.css`. No inline `style={{}}` for static visual values (dynamic values such as a bar width are allowed).
- Short labels never wrap (`white-space: nowrap`); long text is ellipsised.
- Work on branch `redesign`. Run from `DigiMenu-main/`. Browser checks use `npm run dev:local` with `?devAs=superadmin|admin|manager|cashier|barista`.
- After every task: `npm test` → 158+ passing, `npm run build` → succeeds, `node scripts/uiAudit.mjs` → no count higher than before the task.

## Review Focus

1. **Long names and emails** (a 40-character café name, a long owner email) in tables, cards and the sidebar — expect ellipsis on one line, never a taller row. Pinned in Task 2 (`DataTable` cell test).
2. **Unknown or new order status** from the database — expect a neutral `waiting` pill, never a crash or an unstyled word. Pinned in Task 2 (`StatusPill` test).
3. **Menu items without a photo** — expect the neutral placeholder well at the same size, so the grid stays aligned. Pinned in Task 6 (MenuPage test).
4. **Dark theme** — every part must meet 4.5:1 in both themes. Pinned in Task 1 (audit script contrast check runs both token sets).
5. **Empty lists** (no orders, no cafés) — expect `EmptyState` with a next step, not a blank card or an empty table header. Pinned in Task 2 (`DataTable` empty test).

### Task 2: The shared parts — `ui.css` and `src/ui` components

**Files:**
- Create: `src/ui/ui.css`, `src/ui/PageHeader.jsx`, `src/ui/StatusPill.jsx`, `src/ui/StatCard.jsx`, `src/ui/DataTable.jsx`, `src/ui/EmptyState.jsx`, `src/ui/index.js`, `src/ui/ui.test.jsx`
- Modify: `src/main.jsx` (import `./ui/ui.css` after `theme.css`), `src/components/StatusBadge.jsx` (render through `StatusPill`), `src/components/Modal.jsx` (use `ui-dialog` classes; props unchanged)

**Interfaces:**
- Produces classes (values copied from `docs/design-language.html`, renamed with the `ui-` prefix and the Task 1 tokens): `ui-btn` + `ui-btn--primary|quiet|danger|icon`, `ui-chip` (selected via `aria-pressed="true"`), `ui-seg`, `ui-field`, `ui-pill` + `data-tone`, `ui-card`, `ui-page-header`, `ui-toolbar`, `ui-stats`, `ui-stat`, `ui-table`, `ui-product`, `ui-lines`, `ui-ticket`, `ui-panel`, `ui-dialog`, `ui-empty`, `ui-grid`, `ui-touch` (scope that sets `--control-h: 44px`).
- Produces components:
  - `PageHeader({ title, subtitle?, action? })` — `<header class="ui-page-header">`, `title` in an `<h1>`.
  - `StatusPill({ tone, children })` — `tone` ∈ `waiting|preparing|ready|late|paid`; anything else renders as `waiting`.
  - `toneForStatus(status: string): tone` exported from `StatusPill.jsx` — maps the app's existing order/payment/subscription status strings (read them from `StatusBadge.jsx` and `services/orderService`) to a tone; unknown → `waiting`.
  - `StatCard({ label, value, trend?, trendDown? })`.
  - `DataTable({ columns: [{ key, label, align?: "right", render?(row) }], rows, rowKey, empty: { title, body?, action? } })` — renders `EmptyState` instead of a table when `rows.length === 0`; cells are single-line with ellipsis and a `title` attribute carrying the full text.
  - `EmptyState({ title, body?, action? })`.

- [ ] **Step 1: Write the failing tests** in `src/ui/ui.test.jsx`:

```jsx
test("unknown status falls back to the waiting tone", () => {
  render(<StatusPill tone={toneForStatus("some_new_status")}>New</StatusPill>)
  expect(screen.getByText("New")).toHaveAttribute("data-tone", "waiting")
})
test("DataTable shows the empty state instead of an empty table", () => {
  render(<DataTable columns={[{ key: "name", label: "Café" }]} rows={[]} rowKey="id" empty={{ title: "No cafés yet" }} />)
  expect(screen.getByText("No cafés yet")).toBeInTheDocument()
  expect(screen.queryByRole("table")).toBeNull()
})
test("long cell text stays on one line and keeps the full value", () => {
  const name = "The Extraordinarily Long Named Coffee Roasters of Addis"
  render(<DataTable columns={[{ key: "name", label: "Café" }]} rows={[{ id: 1, name }]} rowKey="id" empty={{ title: "x" }} />)
  expect(screen.getByText(name)).toHaveAttribute("title", name)
})
test("PageHeader renders one h1 and the action", () => {
  render(<PageHeader title="Orders" subtitle="Today" action={<button>New order</button>} />)
  expect(screen.getByRole("heading", { level: 1, name: "Orders" })).toBeInTheDocument()
  expect(screen.getByRole("button", { name: "New order" })).toBeInTheDocument()
})
```
